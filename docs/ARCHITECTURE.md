# 技术架构

## 平台与模块

macOS 14+，Swift 6.2+ 工具链（Swift 6 语言模式），SwiftUI + AppKit。
可执行 target `Cliplet` 只包含入口；业务代码位于库 target `ClipletKit`，只公开 `ClipletApp.run()`。
XCTest target 通过 `@testable import ClipletKit` 测试，模块内部再通过类型与构造参数建立边界。

```text
AppDelegate                  组装依赖、生命周期与系统窗口
├── ClipboardMonitor         剪贴板采集、入口隐私过滤
│   ├── ClipboardAccess      系统剪贴板适配 / 测试内存实现
│   └── ImageRecognizing     独立 actor 执行 Vision 识别
├── ClipboardStore           主 actor 上的历史业务状态
│   ├── HistoryPolicy        保留、排序与搜索的纯函数
│   └── HistoryPersistence   串行文件仓库 / 内存仓库
├── ClipboardViewState       查询、过滤、选中项与动作面板状态
├── PasteService             剪贴板写回、权限及目标应用粘贴
├── HotkeyService            Carbon 快捷键注册及恢复
└── AppSettings              注入 UserDefaults 的设置对象
```

预览和演示数据由 App 层装配，Store 不读取进程参数或引用预览工厂。
AppEnvironment 在编译期区分开发/生产身份、设置域与数据目录；演示注入只编译到 Debug。
Models 不依赖 AppKit 或本地化；标题、图标及详情格式位于 UI 扩展。

## 持久化与错误保护

`HistoryRepository` 使用独立串行队列管理读取、250ms 防抖保存、提交与附件清理。
`flush()` 等待已排队任务并提交最新快照，正常退出前调用。临时写入失败保留待保存快照以供重试。
读取失败和首次运行严格区分：仅文件不存在允许空历史写入；损坏、权限问题、非法或无法读取的附件引用
与未知版本保留原文件，并阻止当前实例后续覆盖。附件文件已不存在时只移除该引用，失去图片的图片条目被丢弃，
其余历史照常加载。错误通过 Store 发布给 App 层，不记录正文。

`history.json` 格式为 `{ "version": 1, "items": [...] }`。旧版裸数组按明确迁移分支读取。
图片、RTF、HTML 以内容哈希命名，放入 `Payloads`，JSON 只保存相对文件名。
附件先写成功，再原子替换元数据；只有元数据提交成功后才清理不再被引用的附件。
历史目录权限为 0700，新建附件及元数据权限为 0600。

启动只加载元数据并检查附件引用。预览和粘贴按需读取附件；新采集的内存附件在保存成功后换成文件引用。
读取位置由仓库注入，JSON 不能指定任意绝对路径。每个生产进程组装一个仓库；尚不支持多进程共享写入。

## 采集与后台处理

监听器每 0.45 秒检查 changeCount，先应用暂停、敏感 pasteboard type 与来源排除规则。
采集文本、文件和图片快照后加入 Store。图片 OCR/条码识别在独立 actor 上串行执行，
不阻塞下一次采集；结果只更新仍存在且内容哈希匹配的记录，不重新插入已删除记录。
删除和停止监听会取消相关任务；取消检查阻止排队任务继续执行或把过时结果写回。
粘贴服务记录写入完成后的 changeCount，避免把自己的写入再次采集。

轮询来源仍依据采集时的前台应用，不能当作系统提供的精确剪贴板写入者身份。
Vision 已开始的同步识别不能立即中断，但其结果可以丢弃。

## 历史与界面状态

Store 负责去重、固定、重命名、删除、使用次数和保留策略。类型与内容哈希都相同的重复内容保留稳定 ID 与用户元数据，
刷新内容和来源。固定项优先，其余按复制时间倒序排列。
保留规则在启动、内容变化、设置变化和每 60 秒维护时执行，暂停采集也不暂停清理；实际变更会保存。

`ClipboardViewState` 订阅条目，维护搜索结果与有效选择。搜索为内存子串匹配，支持内容、名称、来源和文件路径。
全文索引、数据库存储和更大规模的性能优化仍可在同一仓库接口之后演进。

## 测试与边界

XCTest 覆盖防抖 flush、重叠保存顺序、损坏/未来版本保护、迁移失败、附件复用与清理、
元数据懒加载、去重、保留策略、独立设置、选择/搜索、采集过滤、后台识别和本地化。
文件测试只写临时目录，剪贴板测试使用内存适配器。

自动粘贴涉及辅助功能授权和焦点恢复，系统集成行为需通过打包应用手动验证。
CI 包含最低系统启动与性能测量，但不代替 UI/权限验收；正式签名与公证由独立手动 release workflow 执行。
